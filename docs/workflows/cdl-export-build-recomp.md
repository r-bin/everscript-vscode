# Workflow: CDL recording → Asar project → ROM + .cdl → C (snesrecomp)

> Status: working end to end on Secret of Evermore since v0.159.1.
> Background and the overall plan: [asm-to-c-port.md](../asm-to-c-port.md).
> Code: `src/emulator/cdl/` ([README](../../src/emulator/cdl/README.md)).

This turns play sessions in the embedded emulator into three things:

1. an **Asar project** that rebuilds the ROM byte for byte, with rooms and strings as
   named, movable pieces;
2. a **`.cdl` file** (which bytes ran as code or were read as data) that follows the
   code when things move;
3. **C source** for the game code, generated by
   [snesrecomp](https://github.com/RetroPortingToolKit/snesrecomp) and seeded with the
   functions the recorder saw.

```text
 play with CDL on ──► CDL library ──► "export asar" ──► export folder
                     (per ROM, merged)                    │
                                       ./build.sh ◄───────┤──► build/out.sfc + out.cdl
                                       ./recomp.sh ◄──────┘──► recomp/project/ (C + .a)
```

---

## 1. Prerequisites

| For | Needs |
|---|---|
| Recording, export | the extension (v0.159.1+) and a ROM loaded in the emulator panel |
| `build.sh` | [Asar](https://github.com/RPGHacker/asar) (tested with 1.90pre), Node |
| `recomp.sh` | a snesrecomp checkout with submodules, Python 3.9+, Rust via rustup, CMake, Ninja, a C compiler |

Get snesrecomp once:

```sh
git clone https://github.com/RetroPortingToolKit/snesrecomp
cd snesrecomp && git submodule update --init --depth 1
```

Only a Windows CLI is released, so on macOS/Linux the first `recomp.sh` run builds
snesrecomp's native analyzer with cargo, which takes about half a minute.

## 2. Record

1. Open the emulator panel and load the ROM.
2. Turn recording on: the **CDL** tab in the bottom bar (this session only), or the
   setting `everscript.cdl.enabled` (every ROM, every session).
3. Play. Coverage only grows where the game actually goes: a room is recorded only
   once it is entered, and a menu only once it is opened. The per-bank strips in the
   CDL tab show what is covered.

Recording is merged into one library per ROM (keyed by SHA-1), across sessions, in the
extension's global storage. On macOS:

```text
~/Library/Application Support/Code/User/globalStorage/rbin.everscript/cdl-library/<sha1>/
```

Paused means idle: no recording, no disk writes. Files are flushed 60 s after the last
change, and immediately on pause, stop, ROM change or close.

## 3. Export

Press **export asar** in the CDL tab. The export goes to `cdl-library/<sha1>/asar/` and
is regenerated completely each time, except for `STEPS.md`, which gets a new entry
appended. **export wram** adds `ram.asm` (every WRAM address with its accessors).

What the folder contains:

| Path | What it is |
|---|---|
| `main.asm`, `banks/bank_XX.asm` | the disassembly; code with caller/access comments, data as `db`/`dw` |
| `rooms/room_XX.bin` | the 127 room blobs, one file each (SoE) |
| `rom.bin` | copy of the ROM; untouched runs and DMA graphics are `incbin rom.bin:<from>-<to>` slices |
| `rom.cdl` | the recorded CDL, 1 byte per ROM byte (Mesen-S / BizHawk bit layout) |
| `export.json` | ROM identity and every label's original offset (used by `build-cdl.js`) |
| `build.sh`, `build-cdl.js` | rebuild the ROM and its CDL (§4) |
| `recomp/cfg/bankXX.cfg`, `recomp.sh` | snesrecomp seeds and runner (§5) |
| `STEPS.md` | one entry per export: what was seeded, coverage, files written |

Before any CDL data is used, the export seeds these **known regions** from the ROM
itself, and they override whatever the CDL says about those bytes:

- `rom_header`, `rom_vectors`
- `room_XX` blobs; the map table at `$9FFDE7` is written as `dl room_XX-$400000 : db $00`
- `str_<index>` for all 3002 strings; the key table at `$91D000` is written as
  `dl strkey(str_XXXX)|$800000` (`|$800000` means compressed)

Because those tables are label expressions, moving a room or a string moves its pointer
too.

## 4. Build the ROM and the .cdl

```sh
cd "<cdl-library>/<sha1>/asar"
ASAR=/path/to/asar ./build.sh
```

Output in `build/`:

- `out.sfc`: reports **byte-identical to the source ROM** while nothing is edited
- `out.sym`: WLA symbol file from Asar
- `out.cdl`: `rom.cdl` remapped by label. Each label owns the bytes up to the next label,
  and its flags are copied to wherever the label landed in the new build.

### Example: move a room

1. In the bank file that holds it, replace
   `room_38:` / `incbin rooms/room_38.bin` with `incbin rom.bin:1E8000-1EABDF`.
   This keeps the old bytes in place, unlabelled.
2. Append to `main.asm`:
   ```asar
   org $F08000
   room_38:
       incbin rooms/room_38.bin
   ```
3. `./build.sh`: the map table entry becomes `$B08000`, and `out.cdl` carries
   room 38's flags to `$F08000`. The old place has no flags.

Rules: a room must start at `$xx8000` or above in its bank, because the engine reads it
through the `$80–$BF` mirror. It must also not cross a bank boundary. Edit `rooms/*.bin`
to change a room's content; a size change is fine because nothing after it moves.

## 5. Generate C with snesrecomp

```sh
SNESRECOMP=/path/to/snesrecomp ./recomp.sh            # uses build/out.sfc, else rom.bin
SNESRECOMP=/path/to/snesrecomp ./recomp.sh other.sfc  # or an explicit ROM
```

What it does:

1. First run only: `snesrecomp build` scaffolds `recomp/project/` (CMake project,
   runner sources, config) and builds the analyzer.
2. Copies `recomp/cfg/bank*.cfg` into `recomp/project/config/`, replacing the old ones.
3. Runs `snesrecomp generate --cfg-roots`, which writes `recomp/project/generated/*.c`.
4. If CMake and Ninja are installed, builds `recomp/project/build/libsnesrecomp_game.a`.

The seeds, from the CDL, one file per bank the code **ran in** (`$80`, `$8C`–`$91`
for SoE; not `$C0`):

```text
bank = 8c
func func_CC9A76 9a76 entry_mx:0,0
# indirect at 9951 -> 8C9A76,8C9A7D,...   (observed; add an indirect_dispatch once the table is known)
```

`bank00.cfg` adds `auto_vectors` and `data_region` lines for the known regions.

### Result on SoE (v0.159.1)

| | roots | function variants | native C | interpreter only | edges |
|---|---|---|---|---|---|
| vectors only | 9 | 61 | 57 | 4 | 722 |
| with CDL seeds (412 recorded entries) | 420 | 1084 | 708 | 376 | 9772 |

That run produced 346k lines of C, no unresolved stubs, and a library that compiles with
AppleClang; it took about 60 s. A re-run after a new export takes about 20 s.

**This is not a playable port.** It is the game code as C functions over a `CpuState`
(`func_C08650_M0X0(CpuState *cpu)`). Making it run needs a host frame driver on top of
snesrecomp's runner, and then the lockstep RAM comparison against the real ROM
([asm-to-c-port.md](../asm-to-c-port.md) §6).

## 6. Getting more out of it

- **Play more.** Every new function the recorder sees is a new root. Export again and
  re-run `recomp.sh`.
- **Resolve the indirect jumps.** The 376 interpreter-only variants mostly sit behind
  jump tables. Each `# indirect at …` comment lists a site and the targets seen so far.
  Turning it into snesrecomp's `indirect_dispatch <site> <count> idx:X tables:<base>`
  (table base and size from the instruction at the site) moves those variants to native C.
- **Mixed entry widths.** `STEPS.md` counts functions entered with more than one M/X
  combination. The cfg gets the first one seen, plus a comment listing the others.

## 7. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `recomp.sh`: cargo not found | rustup puts cargo in `~/.cargo/bin`; `recomp.sh` adds that itself since v0.159.1. Otherwise open a new shell |
| `set SNESRECOMP to a snesrecomp checkout` | export `SNESRECOMP=/path/to/snesrecomp` |
| `build.sh`: ROM differs | expected after edits; unexpected on an untouched export, so re-export |
| Labels "not in the build" in `build-cdl.js` | a label was deleted or renamed in the .asm; its flags are dropped |
| Stale `recomp/project` after a ROM change | delete `recomp/project`, and the next run scaffolds again |
| Strings at a 32 KB chunk end look too long | no string decompressor yet; `STEPS.md` lists how many ends are unknown |

## 8. Legal

Everything in the export folder, including `rom.bin`, the room blobs and the generated
C, is derived from the ROM. It stays in global storage on your machine. Never commit it
or share it.
