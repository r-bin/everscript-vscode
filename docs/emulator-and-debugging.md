# Embedded Emulator & Debug Adapter Protocol (DAP)

> Documentation for the embedded SNES emulator, Map Extension engine, and VS Code DAP debugger.
> Code lives in `src/core/emulator/` and `src/games/evermore/debugger/`.

---

## 1. VS Code Debug Adapter Protocol (DAP)

The extension provides a full VS Code debugger registered under type `everscript` (`package.json:117`):

### 1.1 Debugger Architecture
- **Host Session:** Managed by `src/games/evermore/debugger/dap-session.js` and `src/games/evermore/debugger/debugger-panel.js`.
- **Interpreter Execution Breakpoints:** Injected on the Everscript VM interpreter fetch routine at `$8C:D0A6` (`src/core/emulator/script-debug-host.ts`).
- **Source Maps:** Loads `out/source_map.json` generated by the compiler to map 24-bit SNES ROM bytecode offsets back to exact `.evs` source file lines.

### 1.2 Debugger Capabilities
- **Breakpoints:** Set breakpoints directly in `.evs` source lines.
- **Stepping:** Single-step (`F10`) and step-into (`F11`) at Everscript VM bytecode instruction boundaries.
- **Call Stack & Threads:** Displays active script execution slots (`$7E28FC..$7E2EEA`) as threads, stacking inlined function calls.
- **Variables & Memory Watch:** Inspects script local variables and live WRAM values; supports writing bytes, words, and flag bits.

## 2. Extended Map Engine

The emulator panel (`src/core/emulator/panel.ts`, `panel-webview.ts`) seamlessly renders the surrounding game map beyond the SNES 256×224 screen boundaries:

### 2.1 Multi-Layer Architecture
- **Layer 0 (`#extended-map`):** Mode 1 composite background plus dynamic Section 2 animated tile cycles.
- **Layer 1 (`#extended-entities`):** Live WRAM entity sprites (Boy, Dog, NPCs, enemies, projectiles with 3D elevation offsets).
- **Layer 2 (`#extended-foreground`):** Mode 1 priority canopy tiles and animated foreground overlays.
- **Layer 3 (`#screen`):** Native 512×448 RGBA framebuffer of the core emulator canvas.
- **Layer 4 (`#extended-overlay`):** Step-on triggers (yellow rects), B-triggers (pink rects), and target destination markers.

### 2.2 Live Scroll & Camera Tracking
The engine reads the following verified WRAM registers every frame tick:
- `$7E0112 / $7E0114`: BG2 (terrain) scroll shadow = live camera position (vertical camera is V - 1).
- `$7E010E / $7E0110`: BG1 (canopy) scroll shadow = canopy parallax offset.
- `$7E241F`: Room effect variant.

## 3. Audio Telemetry & Replay Subsystems

### 3.1 Sound-Chip Telemetry (`src/core/emulator/apu-stream.ts`)
- Streams 44.1kHz audio samples and full 64 KB ARAM snapshots directly to the Radar Music tab (`src/games/evermore/music/`).
- Arms non-pausing breakpoint at `$8C:81FD` (`src/games/evermore/emulator/sound-source-view.ts`) to log which entity, animation, or script triggered each sound effect.

### 3.2 TAS Input Recording & Playback (`src/core/emulator/tas/`)
- Frame-exact joypad input recording and replay saved in `.evsmv` format.
- Visual input overlay and fast-forward speed toggle (`#` key).

### 3.3 Runtime Everscript Injection
- Compiles and injects Everscript bytecode into ROM free space (`$C409E4`) and WRAM scratch (`$7EFE00`), activating an idle slot in the script stack (`$7E28FC`) to execute actions immediately in the running game.
