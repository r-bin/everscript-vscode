Resolves a 16-bit script string key into a 24-bit far text pointer via the ROM string key
table at `$91:D000` (key = byte offset, 3 per string). Previously believed: the table is at
`$91:F24A`. If the string is uncompressed, calculates the ROM far pointer directly.
If compressed (bit 15 set), allocates an 80-byte chunk in the cyclic 640-byte text buffer at
`$7F:DC1E` via cursor `$7E:3BBF`, dispatches the DTE/MTE decompression engine at `$8C:CD84`,
and returns the resulting WRAM pointer in DP `$22:$24`.
Full disassembly and clean C reconstruction: `docs/disassembly/ui/dialogue-text-decoder.md`.

## Pointer format
3 bytes, little endian: bits 0-14 the address, bits 15-22 the bank − `$C0`, bit 23 = compressed.
The text sits in the lower half (`$0000-$7FFF`) of a bank `$C0-$FF`; plain text is ASCII ending
in `$00`.

## Keys outside the table
All 3002 table entries point at live vanilla text. Because the index is 24 bits wide, a key of
`$3000 + w` reads its pointer from `$92:w`, and `$92:0000-$1FFF` is the low-WRAM mirror: a script
can write a pointer to WRAM `w` and show its own text without replacing a vanilla string.
