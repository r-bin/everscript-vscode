Runs every frame for each drawn character and decides how it layers with the room's
scenery, from the collision word of the tile it stands on. It writes an attribute word to
`$06`: the low byte is the OAM priority (`$20` = 2, `$30` = 3), the high byte the mask the
OAM assembly (`$809433`) applies to each chunk's own attribute.

## Values
| tile under the character | `$06` | effect |
|---|---|---|
| bits 8–11 = 8 | — | not drawn |
| character's plane below the tile's | `$CC30` | priority 3, in front of everything |
| character's plane above the tile's | `$CC20` | priority 2, behind the priority half of the layers |
| same plane, bit 12 set | `$CC30` | priority 3 |
| same plane, bit 12 clear, bits 8–11 = 4 | `$FC20` | split: chunks marked 1 at priority 3, marked 0 at 2 (wading) |
| same plane, bit 12 clear | `$CC20` | priority 2 |

## Notes
The `$FC20` row is used by no vanilla tile and has not been seen in the running game.
Previously believed: `$FC20` and `$CC20` differ only in which chunk fields survive, not in
depth (`sprite_priority.md` before 2026-10-16). `functions.ts` still names this routine
'Sprite in front of canopy (bit 12)'.
