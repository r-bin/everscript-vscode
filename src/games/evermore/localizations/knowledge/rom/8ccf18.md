Takes a free script slot and points it at the script whose packed pointer is in DP `$26`-`$28`, with its
local bytes and fields cleared. This is where a packed pointer becomes a bus address: bank
`$92 + (p >> 15)`, address `$8000 | (p & $7FFF)`. Callers then link the slot (a call stores the caller in
+`$0B` and pushes the new slot on the run list; a start queues it with `$8C:CE86`).

There is no "pool full" case. With all 20 slots busy, the search walks past `$2F27` into the run
list and the WRAM after it, and takes the first place where the word at +3 happens to be 0. It
writes a slot header and 32 locals there and queues that address as a thread. Nothing recorded
shows this happening yet; it is the likely cause of crashes when many event scripts start at once
(`docs/disassembly/combat/spell-targeting.md` §4).
