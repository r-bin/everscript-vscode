Sets up one colour-cycle slot. The room loader at `$9090A6` calls this once for each three-byte room descriptor. The packed first byte (`b0`) selects an even cycle-state table offset `X = (b0 & 0x70) >> 3` (`0, 2, .. 14`, two slots per palette) and recombines `(X << 3) + (b0 & 0x0F) = b0 & 0x7F` as the starting CGRAM colour index (palette `(b0 >> 4) & 7`, colour `b0 & 0x0F`). If slot `X` is already active for a different starting colour on the same palette, `INX` selects the odd partner slot `X + 1` (e.g. room `0x3D` runs both `21 09 01` and `2A 04 05` on palette 2). The second byte (`b1`) supplies the colour span, and the signed third byte (`b2`) supplies the rate and direction. The routine stores the starting CGRAM colour in `$1372,X`, the signed rate in `$13D2,X`, and the direction-specific step/counter state in `$13F2,X`, `$1392,X`, and `$13B2,X`. Script opcode `0xB6` also uses this routine, and `$90:D569` ticks active slots during `per_frame_map_effects` (`$90:9839` -> `$90:CBB3`).

Previously believed: this routine reserved extra CHR graphics for room descriptors, or doubled the upper nibble via `b0 + (b0 & 0x70)`. Both were incorrect; `$90D50F` sets up CGRAM palette colour cycling at `b0 & 0x7F`.
