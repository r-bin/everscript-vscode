Part of a routine (entered at `$80:CFA9`) that copies one 64-byte row of a word table at `$80:E293`
(row number in `$7E14C6`) into WRAM. The first pass reads the words through bank `$80` and adds
`$7E14C8` (to `$7E2050+`). This second pass reads the same offsets byte by byte. But it first
switches the data bank to `$B0`, so it reads `$B0:E293+X`, which is file `0x30xxxx`. That area is
past the end of the 3 MB ROM.

What the game gets there depends on the hardware or emulator (see the `snes-memory-mapping` skill
§6). On the bundled snes9x2005 core it happens to be the same table as the first pass (bank `$80`).
That suggests the developers meant `$80`, and that a real cartridge returns unrelated bytes.

## Notes
- Any ROM layout that puts data at file `0x30E653–0x30E6D1` changes this read. That includes our
  4 MB ROM export, whose extension code area starts at `0x308000`. The ExHiROM build keeps the
  cartridge's answer there.
- The purpose of the `$7E2050`/`$7E2090` tables is unknown.
