`CALL <id>` with a one-byte id. The id is **not** an offset into the trigger pointer table at
`$92:8000 + word[$92:8000]` (that is what trigger ids and opcode `0xa4` use): the handler adds a
second header word, `word[$92:8008]` (`$1677` in vanilla), so

`pointer = $92:8000 + id*3 + word[$92:8008] + word[$92:8000]`, then unpack the packed pointer.

Previously believed: id*3 into the trigger table — that lands in sniff-spot scripts, not in
the globals. `Machine.globalScript()` implements the formula.
